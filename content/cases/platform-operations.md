## 컨테이너가 떴다는 사실만으로는 부족했습니다

현대오토에버에서 스마트팩토리 공통 백엔드 경험을 거쳐 MLOps 플랫폼 운영으로 역할을 넓혔습니다. 배포 명령이 끝나는 것, Pod가 기동하는 것, 요청에 올바른 결과가 돌아오는 것은 서로 다른 확인입니다.

수동 이미지 빌드와 배포를 자동화하는 일부터, 배포 뒤 서비스별 결과를 확인하고 운영 현황을 공유하는 일까지 연결했습니다.

## 반복 배포를 공통 경로로 만들었습니다

GitLab CI/CD, Harbor, Helm 기반으로 개발계 9개 ML 서비스의 CI/CD를 구축했습니다. 배포 전에는 Helm Diff, 설정과 Kafka Topic 의존성을 확인하고, 배포 후에는 Rollout과 Pod 상태·로그를 확인하는 흐름을 정리했습니다.

> 9개 서비스는 개발계 구축 범위입니다. 모든 운영 서비스의 CD가 완료됐다는 뜻이 아닙니다.

## 비동기 요청은 접수 다음의 상태를 검증해야 했습니다

FastAPI 기반 E2E 검증 서비스를 구축해 테스트 요청, 콜백 수신, 결과 조회를 연결했습니다. External Gateway에서 요청 UUID가 달라지는 경로와 서비스마다 다른 콜백 조건을 반영했습니다. 접수 성공을 최종 처리 성공으로 해석하지 않는 것이 중요한 판단이었습니다.

| 검증 범위 | 기록으로 확인한 결과 |
|---|---|
| 개발계 동기 4개 서비스 | 서비스별 10/10 통과 |
| 운영계 APS 비동기 | 콜백 수신 및 정상 결과 코드 확인 |
| CI 자동 test stage 연동 | 후속 과제, 완료 성과에서 제외 |

## 관측 결과가 공유되는 경로도 자동화했습니다

Grafana 대시보드 11개를 공통 지표로 구성하고, 5개 그룹의 PDF 리포트를 주간 자동 발송하도록 구축했습니다. 한글 첨부파일, MIME 구조, 메일 환경의 오류를 해결해 배포까지 연결했습니다.

이 작업의 결과는 모델 추론 성능 향상이 아닙니다. **배포 절차, 결과 확인, 운영 정보 공유를 담당자의 기억과 수작업에 덜 의존하도록 만든 것**입니다. 대시보드 수, CI/CD 서비스 수, E2E 검증 서비스 수는 서로 다른 대상을 세므로 합산하지 않습니다.
