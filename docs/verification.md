# V1 샘플 검증 기록

2026-11-04 KST. 기존 블로그와 이력서/포트폴리오 원본은 변경하지 않았다.

## 자동 검사
- `npm test`: Markdown 변환/HTML·URL 안전성, metadata/slug, 코드 블록 목차, 실제 파일 생성·수정·백업·휴지통 이동, 초안 제외, 잘못된 편집 시 기존 원문 보존, 경로 이탈/심볼릭 링크 차단, Host·Origin·CSRF 검사.
- 임시 프로젝트의 HTTP 통합 검사: 새 초안 → 미리보기 → 로컬 공개 저장 → 글 확인 → 삭제 → 404. 외부 Origin과 잘못된 CSRF는 403, 경로 이탈은 400. 사용자 원본을 테스트 데이터로 수정하지 않음.
- `npm run build`: 공개 문서 5개, HTML 8개(홈·노트 목록·상세 5개·404).
- `npm run check`: 로컬 링크/asset/목차 147개, h1·한국어 metadata, 초안·로컬 편집기 제외 통과.
- `node --check`: 공개 app.js와 로컬 studio.js 통과.
- GitHub Pages workflow는 준비만 했으며 GitHub 저장소 생성·실행은 하지 않았다.

## 실제 Chrome 확인
- owner-private Sites 배포 성공. 소유자 로그인 후 화면 확인.
- 1440px: 첫 화면, 메인 전체 섹션, 노트 목록을 시각 확인. 페이지 가로 폭 1440px.
- 390px: 홈·인증 캐시 상세 시각 확인. viewport/page/body 390px로 가로 넘침 없음.
- 320px: 홈·인증 캐시·금융·플랫폼 사례의 가로 폭 320px 확인. 사례 간 링크 동작.
- 모바일 메뉴 열기 및 노트 이동.
- 노트 검색 ‘캐시’ 1개, 없는 검색어의 빈 결과, 검색 초기화 후 분류 1개, 전체 2개 확인.
- 브라우저 console error 0건. 임시 viewport는 기본값으로 복원.

## 수정
- 모바일에서 줄바꿈을 감춘 경력 지도 문장의 쉼표 뒤 공백 보완.
- 플랫폼 사례 제목을 ‘배포 완료에서, 서비스 정상까지’로 줄여 고아 단어 줄바꿈 완화.
- 코드 블록 안의 ##를 목차에서 제외하는 회귀 테스트 추가.
- 노트 검색 폼의 inline handler를 제거하고 외부 script에서 submit을 제어.

## 검증 경계
- 로컬 주소는 브라우저 제어 환경에서 ERR_BLOCKED_BY_CLIENT로 차단되어 로컬 에디터 UI를 클릭 검수하지 못했다. HTTP 저장/삭제 흐름은 임시 프로젝트에서 테스트했다. 정적 사이트는 비공개 배포에서 브라우저 검수했다.
- 접근성 전용 도구/스크린리더, 모든 OS/브라우저, GitHub Actions 실제 배포는 미검증. WCAG 인증을 주장하지 않는다.
- 실제 경력 수치는 사용자 보관 기록에 근거하며 이번 구현에서 독립 실측하지 않았다. 공개 승인은 별도 확인 대상이다.


## 2026-11-06 — GitHub Pages 및 발행 흐름 정비
- 프로젝트 하위 경로의 깊은 404에서 자산·홈·메뉴 경로, RSS/sitemap, robots 경로 검증을 추가했다.
- 잘못된 배포 URL이 기존 산출물을 삭제하기 전에 실패하는지 검사했다.
- 글 상태 CLI가 초안/빌드 대상을 구분하고 파일·산출물을 변경하지 않는지 검사했다.
- 테스트 총 13건과 기본/프로젝트 경로 각각 147개 링크·자산 검사를 통과했다.
- src/와 content/ 및 기본 URL의 dist는 V1과 동일하다. 디자인·본문을 변경하지 않았다.
- GitHub가 현재 요금제에서는 비공개 저장소 Pages를 지원하지 않는다고 422 응답했다. 공개 전환은 승인 대기이며 실제 배포·배포 후 브라우저 검증은 아직 하지 않았다.


### 공개 전환 승인 후
- 사용자 승인에 따라 저장소 visibility=public을 확인했다.
- GitHub Pages를 build_type=workflow로 활성화하고 배포 주소를 확인했다.
- Git 전체 추적 이력의 알려진 자격증명 패턴 검사는 통과했다. 포괄적인 기밀 감사를 대신하지 않는다.
