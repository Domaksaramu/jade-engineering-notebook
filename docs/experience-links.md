# 경력 흐름과 프로젝트 연결

2026-11-06. 디자인은 유지하고 공개 글의 맥락과 탐색을 보강했습니다. 글 본문과 성과 수치는 변경하지 않았습니다.

## 방문자의 경로

- 홈의 기존 경력 맵 → 금융 연동 / 공통 기반 / 플랫폼 운영 페이지.
- 노트 목록의 “경험의 흐름으로 읽기” → 해당 흐름의 프로젝트 사례와 기술 글.
- 프로젝트 사례 → “이 프로젝트의 기술 글” → 원래 사례로 돌아가는 양방향 링크.
- 다른 프로젝트지만 같은 관심 흐름인 글 → “같은 경력 흐름의 다른 글”로 구분.
- 검색에는 제목·요약·기술 외에 회사·프로젝트·역할·경력 흐름도 포함.

모든 연결은 정적 HTML입니다. 경력 흐름 탐색과 글 읽기는 JavaScript 없이 동작하며, 기존 검색·분류만 JavaScript를 사용합니다.

## Markdown 메타데이터

일반 노트에 새 필드를 강제하지 않습니다. 경력 흐름에 연결할 때는 네 필드를 모두 작성합니다.

```text
company: "다우기술 · 키움저축은행"
project: "소비자금융 인증 캐시·JVM 안정화"
role: "장애 원인 분석 · 캐시 로직 개선 / 단독 수행"
journey: "shared-foundation"
relatedCases: ["auth-cache"]
```

- `journey`: `financial-integration`, `shared-foundation`, `platform-operations` 중 하나. 표시 이름·순서·소개는 `src/experience.mjs`에서 관리하는 편집적 분류입니다. 재직·프로젝트 사실을 추론하는 로직이 아닙니다.
- `company`, `project`, `role`: 확인된 공개 문구만 사용합니다. 기존 회사 필드의 회사/고객사 또는 수행 환경 표기를 유지했습니다.
- `relatedCases`: **노트에만 선택적으로** 작성하는 동일 프로젝트 사례 slug 목록입니다. 사례에는 역방향 필드를 중복 관리하지 않습니다.
- 동일 프로젝트 연결은 회사·프로젝트·경력 흐름이 일치해야 합니다. 실제로 다른 프로젝트의 글은 `relatedCases`에 넣지 않고 같은 `journey`로만 연결합니다.
- 대상 없음·잘못된 자료형·중복 slug·다른 프로젝트 연결은 검증에서 거부합니다. 연결 대상이 초안이면 공개 화면의 링크에서 제외합니다.
- 에디터 저장/삭제도 제안된 연결 관계를 먼저 검증합니다. 연결을 깨는 변경은 원문과 백업을 건드리기 전에 거부합니다. 사례를 삭제하려면 참조하는 노트의 `relatedCases`를 먼저 정리합니다.
- 공개 저장소에서 `draft:true`는 원문 비공개 기능이 아닙니다. 미승인 초안과 근거표는 `_private/`에서 검토합니다.

## 이번에 적용한 관계

| 경력 흐름 | 프로젝트 | 사례 ↔ 기술 글 |
|---|---|---|
| 금융 연동 | 혁신금융 신용조회·한도조회·대출 연동 (2020–2021) | `financial-integration` 사례. 아직 연결된 기술 글 없음 |
| 공통 기반 | 차세대 소비자금융 리뉴얼 (2022–2023) | `local-financial-integration` 기술 글. 같은 프로젝트의 별도 사례는 아직 없음 |
| 공통 기반 | 소비자금융 인증 캐시·JVM 안정화 (2023) | `auth-cache` ↔ `object-lifetime` |
| 플랫폼 운영 | MLOps 배포·E2E 검증·운영 리포팅 | `platform-operations` ↔ `after-deployment` |

차세대 리뉴얼과 인증 캐시 안정화는 서로 연결되는 경력 맥락이지만 이번 자료에서는 별도 프로젝트 항목으로 유지합니다. 2020년 금융 연동과 2022년 차세대 리뉴얼도 동일 프로젝트로 묶지 않습니다. 경력 연도는 기존 글의 기록 시점을 유지하며 새 성과나 재직 사실을 추가하지 않았습니다.

## 검증

연결 방향·메타데이터·없는 대상·다른 프로젝트·초안 제외·HTML escape·빈 상태·사이트맵·편집 시 원본 보존을 회귀 검사합니다. 브라우저/배포 검증은 수행 결과와 한계를 별도로 기록합니다.
