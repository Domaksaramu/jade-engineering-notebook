# Codex 요청 양식 — 초안 작성까지만

아래 경로·slug·주제를 실제 값으로 바꿔 사용합니다. 자료에 없는 근거나 실패 사례를 생성하지 않습니다.

```text
이 저장소의 AGENTS.md, docs/content-policy.md,
docs/editorial-workflow.md, docs/experience-links.md를 먼저 읽어.

목표: [주제]를 하나의 기술적 판단 중심으로 정리한 비공개 경험 노트.
slug: [english-slug]
입력 자료: [공개 가능한 자료의 정확한 파일 경로 목록]
추가 조사: 별도 요청 전에는 입력 자료 외의 이력·회사 자료를 탐색하지 마.

1. npm run draft -- [english-slug]로 _private/drafts/notes/에 초안을 만들어.
   이미 있으면 덮어쓰지 말고 기존 내용을 먼저 확인해.
2. 회사·프로젝트·기간·본인 책임을 구분하고,
   상황 → 관찰 → 대안/선택 이유 → 변경 → 검증/한계 → 다음 기준으로 써.
   일반 학습 글이라면 회사 경력을 억지로 연결하지 마.
   화자는 경험 당사자야. 확인된 역할·성과는 “담당했습니다”, “제 기여도는 40%입니다”처럼 직접 서술해.
   “기록돼 있습니다”, “경력 기록에서 확인됩니다” 같은 제3자 전달 표현 대신, 필요한 측정 범위와 한계만 설명해.
3. 사실·해석·추후 제안을 분리해. 원천에 없는 코드·로그·수치·인과관계는 만들지 마.
   내부 주소·개인정보·토큰·비공개 코드를 복사하지 마.
   모르는 부분은 질문으로 보고하고 그 자리를 성과처럼 확정하지 마.
4. 회사·프로젝트가 같다는 근거가 있을 때만 relatedCases를 지정해.
   그렇지 않으면 같은 journey의 다른 경험으로만 구분해.
5. npm run review -- [english-slug]를 실행해.
   안전하게 해결 가능한 작성 안내·메타데이터 오류를 고치고 다시 검토해.
   사실이나 기밀을 확신할 수 없으면 원문을 공개 경로로 옮기지 말고 질문해.
6. 초안 경로, 핵심 판단, 근거/미확인 항목, 검토 결과와 hash를 보고해.

중단 조건: 비공개 초안과 검토 결과 보고까지.
prepare, 승인 옵션, Git add/commit/push, PR 병합, 배포, 예약 작업 등록은 하지 마.
checksPassed:true를 사실 검토·기밀 검토·공개 승인으로 간주하지 마.
```

사용자가 별도로 현재 원문의 공개를 승인한 뒤에만 발행 준비·검증·PR 절차로 진행합니다. 이 문서는 요청 양식이며 Codex 예약 자동화를 실제로 등록한 상태는 아닙니다.
